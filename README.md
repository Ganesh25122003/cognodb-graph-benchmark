# Graph Database Cloud Benchmark

Benchmark suite for comparing CognoDB Cloud with other graph database platforms using the same public graph dataset and logically equivalent workloads.

## Assignment

This project was created for the Wexa AI Graph Database Cloud Benchmark take-home assignment.

The assignment requires CognoDB plus at least four other graph databases, the same dataset and workloads, percentile-based latency measurements, ingest throughput, mixed workload throughput, resource/footprint reporting, reproducible automation, and honest documentation of limitations.

### Comparison Platforms

The assignment requires at least four additional graph databases.

Those comparison platforms were not available in the current execution environment, so no comparison measurements have been fabricated.

This repository contains the benchmark framework and the real CognoDB measurements. Additional platform results must be generated by running the same workloads against actual database instances.

- 100 operations

## Measurement Methodology

Read workloads use warm-up iterations followed by repeated measurements.

Latency is reported using:

- minimum
- p50
- p95
- mean
- maximum

Traversal start nodes are sampled from the generated dataset.

The same logical workloads should be used for every comparison platform.

## Ingestion

The dataset was successfully loaded into CognoDB:

- Nodes: 91,489
- Relationships: 200,000
- Method: Bolt driver with batched Cypher `UNWIND` / `MERGE`
- Batch size: 250

The successful run did not record wall-clock ingestion time, so nodes/sec and relationships/sec are marked as not recorded rather than estimated.

## Resource Footprint

## Fairness

For a complete multi-platform comparison:

- identical dataset
- equivalent resource allocation
- same logical workloads
- same client machine
- same region where possible
- warm-up before measurements
- repeated measurements
- p50/p95 reporting
- documented platform-specific caveats
